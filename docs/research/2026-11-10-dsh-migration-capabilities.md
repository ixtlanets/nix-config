## Эксплуатация и приватность

На VM уже есть exact runtime pins, systemd/linger, authenticated readiness, snapshot/rollback. [Runbook](../dsh-omarchy-vm.md#L90-L116) требует согласованного снимка всей DSH state с остановленными writers. Rollback перематывает сессии и credentials; локальные snapshots не заменяют off-host backup. Codex OAuth отдельно авторизован на VM; нельзя копировать вращающиеся grants из OpenClaw или другого DSH ([OAuth runbook](../dsh-omarchy-vm.md#L47-L61)).

Перед переносом чувствительных рабочих контекстов отдельно проверить live privacy overrides. В rc.1 OTel по умолчанию `FEEDBACK_ONLY`: новое явное feedback разрешает отправку canonical prefix с контекстом для всех провайдеров, не только DeepSeek. `DISABLED` не создает transport. [OTel README:12–14,32–72](</home/nik/.local/share/mise/installs/npm-deepseek-ai-dsh/0.2.2-rc.1/node_modules/.mise/@deepseek-ai+dsh-session-telemetry-otel@0.2.2-rc.1_2c19c38157a3661470c6680026919ac3/node_modules/@deepseek-ai/dsh-session-telemetry-otel/README.md#L12-L72>).

Отдельный default-on session-log contributor касается **official DeepSeek API requests**, а не произвольного Codex inference: [Session-log README:10–36](</home/nik/.local/share/mise/installs/npm-deepseek-ai-dsh/0.2.2-rc.1/node_modules/.mise/@deepseek-ai+dsh-session-log-deepseek@0.2.2-rc.1_@deepseek-ai+cordis@4.1.0_@deepseek-ai_72f44b0d62b7a81dd64cab8ee726ca13/node_modules/@deepseek-ai/dsh-session-log-deepseek/README.md#L10-L36>). Фактические overrides VM и факт отправки телеметрии этим аудитом не установлены; это вопрос проверки, а не утверждение об утечке.

## Оценка

Интерактивную агентную работу и часть расписаний переносить технически реалистично. Полную замену OpenClaw нельзя объявить готовой без живых проверок Telegram, heartbeat/уведомлений, MCP userbot/browser, ролевых контекстов и памяти. Критичную автоматику разумно оставить детерминированным сервисам/таймерам с журналом результата и idempotency, а не полагаться на факт доставки запроса агенту.
