# DSH private vault pilot: финализация сохранения результатов обследования

Статус: **done** (сохранение выполнено и проверено; приёмка уточнена отдельным
коммитом `ef09b054`). OCR: ограничения распознавания перенесены в карточки, но не
блокируют сохранение. Отдельно: неполное распознавание ≠ незавершённое сохранение.

Поправка приёмки: обе карточки имеют `ocr_status: partial`. Ранее первая карточка
была помечена `complete`, а расхождение в годе даты документа и годе рождения
закрывалось «вариантом большинства страниц». Для идентифицирующих полей это
недопустимо: большинство не является независимым подтверждением. Дата документа
теперь не утверждается (`document_date: null`,
`document_date_status: needs_review`, `date_source: telegram-message-received`),
дата рождения в карточке человека не корректировалась. Подробности -
в [аддендуме по датам](2026-11-10-dsh-private-vault-pilot-date-review.md).

## Группировка страниц

Группировка детерминированная, по содержимому, а не по соседству сообщений:
совпадение учреждения, названия исследования, пациента и набора печатных дат.
Итог: два документа по две страницы (`2 + 2`). Оба документа - разные
исследования, полученные в один день; поэтому у них разные имена файлов и разные
карточки. Совпадение даты в именах файлов - это дата получения в Telegram, а не
подтверждённая дата исследования.

Локальная модель отдельно опрашивалась на «одна это страница одного документа
или два разных». Её попарные ответы оказались нетранзитивными (страницы 1-2
«одно», 3-4 «одно», 2-3 «одно», 1-3 «разное»), поэтому вердикт модели не
использовался как основание: он только сверялся с детерминированной
группировкой. Расхождение решалось в пользу печатных метаданных.

## Достоверность фактов (source grounding)

Значения не порождались моделью. Факты строятся детерминированно из
валидированного OCR-текста: строки таблиц и строки вида «показатель: значение»
копируются дословно, с номером страницы и цитатой-строкой. Модель применялась
только для полей шапки документа (тип, дата, учреждение, пациент, название
исследования) и для сверки личности; каждое такое поле принималось лишь при
условии, что оно является точной подстрокой распознанной страницы. Всё, что не
совпало дословно, отбрасывалось и фиксировалось как ограничение, а не
нормализовалось. Исключение - дата документа: там дословной подстрокой были
подтверждены разные варианты на разных страницах, поэтому поле осталось
неразрешённым (см. «Ограничения OCR»).

Единицы измерения и референсные интервалы в распознанном тексте не выделены,
поэтому таблица в карточках - «показатель - значение» без выдуманных единиц;
это прямо указано в разделе качества извлечения. Сравнение с предыдущими
записями не выполнялось: совпадений по показателю и единицам не найдено, и это
зафиксировано как «сравнение не проверено», а не как отсутствие динамики.

## Ограничения OCR

Обе карточки имеют статус `partial`. Часть области страниц не распознана
надёжно (рукописные/краевые фрагменты); неразборчивые значения не добавлялись.

Отдельно - расхождение в идентифицирующих полях: на одной странице OCR прочитал
год даты документа и год рождения с расхождением в одну цифру относительно
остальных страниц. Вариант большинства **не** принимался как установленное
значение. Независимая локальная проверка только по датам (4 запроса, по одному
на страницу, те же прямоориентированные копии изображений) согласованного
значения не дала: `date_verified: false`, неразрешённых полей - 2. Поэтому дата
документа не утверждается, а дословные варианты по страницам с атрибуцией
источника вынесены в раздел качества извлечения обеих карточек. Годы и сами
значения в отчёте не воспроизводятся.

## Границы приватности

- Медицинские изображения, полный OCR-текст и извлечённые значения оставались
  локально на `omarchy-vm`; облачная модель их не получала - все такие чтения
  выполнялись локальным Python.
- Облачный отчёт содержал имя пациента и названия исследований: это те же
  метаданные, что уже видны в финальных ссылках на карточки. Корректная
  формулировка: облако получило статусы прогона и минимально необходимые для
  фиксации метаданные, а не изображения, не полный OCR и не значения. Здесь эти
  метаданные повторно не воспроизводятся.
- Исходящие запросы - только литеральный LAN-эндпоинт
  `http://192.168.1.174:8081/v1/chat/completions`, модель
  `unsloth/Qwen3.6-35B-A3B-MTP-GGUF:UD-Q4_K_M`, без прокси и без редиректов.
- Сырой OCR и ответы модели остались в приватном кэше (права 0600, каталог
  0700), в карточку перенесены только атрибутированные факты, не транскрипт.
- Новые файлы созданы с правами 0600; существующие каталоги и права карточки
  человека не менялись.

## Проверка после записи

- `vault-commit --dry-run` затем реальный коммит; в коммите ровно 7 путей,
  ничего чужого. Правка приёмки - отдельный коммит `ef09b054`, ровно 3 пути
  (2 карточки + карточка человека).
- 66 чужих незакоммиченных путей (в том числе параллельная аудио-обработка)
  не тронуты.
- Файлы задачи после коммита чистые (`git status` по папке здоровья - 0).
- Indexary: обе карточки отдаются с HTTP 200 (проверено и после правки;
  имя хоста резолвится через tailscale-узел).
- Независимая приёмка лидера после правки: повторно проверены четыре исходных
  SHA-256, четыре сохранённых оригинала, каноническая валидация OCR-кэша,
  YAML и двусторонние ссылки. Исходный коммит содержит ровно семь путей,
  корректирующий - три; в карточке человека относительно исходного состояния
  только четыре вставки, удаления отсутствуют. Файлы задачи чистые.
- Повторный поиск семантических кандидатов без использования спорной даты:
  внешних кандидатов нет для обеих карточек. В обеих явно указаны дата получения,
  `document_date: null`, `document_date_status: needs_review`, OCR `partial`.

## Замечания на будущее

- Локальная модель на этом стенде плохо копирует длинные значения дословно:
  при свободной формулировке промпта она перефразирует названия показателей.
  Рабочая схема - детерминированное извлечение строк + модель только для полей
  шапки, с проверкой «точная подстрока страницы». Это стоит закрепить в
  библиотеке стейджера как единственный режим.
- Для идентифицирующих полей (дата документа, дата рождения) «вариант
  большинства страниц» не является подтверждением: при любом расхождении поле
  остаётся неразрешённым, а карточка - `partial`. Это правило стоит закрепить
  в стейджере как fail-closed.
- Попарные вердикты модели о «тот же документ» нетранзитивны; для группировки
  нужны печатные метаданные (учреждение, исследование, пациент, дата), а
  вердикт модели - только как дополнительная сверка.
